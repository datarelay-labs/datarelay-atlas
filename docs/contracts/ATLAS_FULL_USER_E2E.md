# Atlas Full User E2E Contract

## Scope and execution

After Surface Reconciliation, prove the actual ChatGPT/MCP user mission on the
SAME immutable candidate (ADR-0023). This is AI_DIRECT by CHATGPT_CHAT; no owner
GUI test is required. Retain real-browser coverage of the auxiliary UI. A
standard TLS MCP client or live REPL is a transport mechanism; ChatGPT chooses
actions, interprets returned context and checks it against canonical Git/GitHub.
Do not substitute internal service calls, unit tests or scripted scenarios for
the actual MCP user. Human-owner mode remains an explicit optional run choice
under HUMAN_OWNER_WITH_CHATGPT_AUDIT, never a default dependency.

## Required starting state

Use a clean immutable checkout; dirty/untracked bytes invalidate evidence.
Read this complete contract. Bind HEAD, committed contract digest, runtime
archive/file hashes, isolated fixture scope, client/browser versions and run ID.
Use at least two projects, attributable engineering and personal sources, and
known valid/invalid lifecycle fixtures. Do not log tokens, private keys or real
customer content. Never represent synthetic fixture state as real project usage.

## Mission A — resume and use engineering context

A1. Discover/select the project using real list_projects/bootstrap_datarelay_context.
A2. Call get_task_context for the known project/workstream; inspect source refs,
currentness, Work Packet/PR HEAD and UNKNOWN channels.
A3. Form a relevant query from that task; search_project, follow the returned
identity with get_provenance, and inspect get_source_detail.
A4. Compare the claimed repository/path/revision and work state with independent
canonical fixture or live GitHub facts. Use those checked facts to choose the
actual next repository action; record that action, not just a successful request.
A5. Create a fresh MCP client session and repeat scoped retrieval; persisted source
identity and contents must remain consistent, with no canonical writes.

## Mission B — scope, authority and mistakes

B1. Search a marker present in one project and absent in another; no scope leak.
B2. Use search_knowledge with explicit project_ids; compare scoped results and
verify engineering vs personal_search non-authoritative classification.
B3. Exercise invalid workstream/unknown project/absent cross-project scope and
recover using tool-returned guidance. Unauthorized/wrong-scope access rejects.
B4. Valid lifecycle becomes OBSERVED; missing evidence is UNKNOWN, stale evidence
is STALE, invalid evidence UNAVAILABLE. Never infer CI/release PASS from context.
B5. Unavailable/corrupt projection is rejected; restore only the test-owned fixture
and confirm actual MCP and browser recovery without serving stale authoritative data.

## Mission C — operations and auxiliary browser parity

C1. Call get_operations_readiness on a state root containing legitimate durable
metadata; check health/storage counts and lack of release authority.
C2. Correlate actual TLS tools/call SUCCESS/BLOCK/ERROR outcomes with minimal tool
execution log records; distinguish HTTP handshake/health counts from tool events.
Verify arguments, returned data, tokens and caller identity are absent from audit
records. Efficacy counts are observations, not automatically incremented by probes.
C3. Through real Chromium/Chrome navigate overview -> project -> source -> search
-> lifecycle, compare source revision, personal labels and derived truth with MCP;
reload/open a fresh browser context and check persistent readback.
C4. Preserve actual-browser negative regression: unknown project/route, invalid
input, invalid lifecycle/projection, inert markup, security headers and a rejected
POST/write attempt with persistent data unchanged. Browser failure still blocks.
C5. Stop run-owned clients/browser/test listeners, restore disposable altered
fixtures and record cleanup truth. Do not remove unrelated worktrees or sources.

## Production verification and honest completion

After exact-candidate user gates, affected machine/CI checks, rollback qualification
and the applicable owner-approved production change, call the native connected
Atlas MCP: scoped resume/search/provenance/readiness. Match server tool events to
those real ChatGPT calls and use retrieved context in actual repository work.
A local test credential is not proof of production OAuth; native post-cutover
calls close that distinct integration check. Revert the approved code cutover on
health/native-MCP failure. No credential/permission/network changes are implied.

## Evidence and pass rule

Preserve per-action timestamps, expected/observed responses, canonical comparison,
client/browser identity, raw bounded evidence, private-data protection and cleanup.
100% applicable missions, zero mandatory FAIL/PARTIAL/BLOCKED or unresolved finding,
same HEAD and independent ChatGPT audit are required. Old browser PASS is not
relabelled as this MCP user journey. An incomplete/blocked former run remains so.
Structural JSON validation cannot authenticate actors, freeze a candidate, merge,
publish a release or grant production permission. Batch-fix frozen findings, then
run a complete fresh confirmation on the new candidate before quality closure.
